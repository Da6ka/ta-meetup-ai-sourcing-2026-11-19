# Мой первый скилл для сорсинга

Дома вы сделаете скилл, который помогает расширять поисковый запрос. Скилл здесь означает сохранённую инструкцию для Codex. Её можно вызвать снова, когда появится другая вакансия. Для упражнения хватит примеров ниже.

1. **Откройте папку в Codex.** Создайте на компьютере пустую папку «Практика сорсинга». Откройте её в Codex как проект и начните в ней чат.
2. **Дайте Codex задачу.** Отправьте в чат: «Ищу аналитика продукта с подпиской. Мой запрос subscriptions находит А: “tracked subscriptions”, но пропускает Б: “tested first payment after trial”. Предложи запрос, который найдёт обоих. Для каждого покажи, какие слова совпали».
3. **Проверьте ответ на лишнем совпадении.** Отправьте: «А вот В: “tested newsletter signup after trial”. Это подписка на рассылку. Проверь свой запрос. Если он находит В или теряет А либо Б, исправь его. Покажи совпадения ещё раз». Возможный ответ: subscriptions OR "first payment".
4. **Попросите Codex сохранить правило в файл.** Отправьте в тот же чат сообщение для шага 4 внизу страницы. Когда Codex закончит, попросите показать созданный файл и прочитайте правило. Оно должно подходить и для другой вакансии.
5. **Попробуйте скилл в новом чате.** В той же папке начните новый чат и отправьте: «Используй $my-sourcing-search. Ищу рекрутера. Запрос sourcing находит А: “led sourcing”, но пропускает Б: “found engineers through GitHub”. Предложи запрос для А и Б».
6. **Проверьте результат сами.** Возьмите В: “published code on GitHub”. Проверьте по словам: А и Б должны попасть в выдачу, В должен остаться за её пределами. Если он ищет всех со словом GitHub, покажите Codex пример В, попросите уточнить правило в файле и повторите шаг 5.

## Сообщение для шага 4

> Создай в этом проекте скилл my-sourcing-search. Сохрани его в .agents/skills/my-sourcing-search/SKILL.md с именем и описанием. Запиши правило: когда я даю поисковый запрос и примеры профилей, предложи одно изменение. Покажи, кого запрос теперь найдёт и по каким словам. Попроси пример лишнего совпадения и проверь запрос на нём. Слова из учебной вакансии каждый раз заменяй словами из нового брифа.

## Бриф на одну вакансию

| Вопрос к нанимающему менеджеру | Ваш ответ |
|---|---|
| Какое решение или задачу вы доверите человеку в первые месяцы? | |
| Какой пример из прошлого опыта убедит вас позвать его на встречу? Какой похожий опыт тоже подойдёт? | |
| Какие условия обязательны? Укажите географию, рабочие часы, бюджет и формат сотрудничества. | |
| В каких компаниях и командах люди уже решают такую задачу? По какому признаку это можно проверить? | |
| Какими словами человек мог описать эту работу в профиле? Какие ещё должности стоит поискать? | |
| Что можно подтвердить по открытому источнику, а что придётся спросить лично? | |

## Справочные материалы

**Выберите компанию-донора.** Запишите название команды, задачу, которая похожа на вашу, и ссылку на публикацию или вакансию, где эта задача описана. Для ориентира можно посмотреть, как устроена карта рынка. [Учебный пример talent-intel](https://github.com/SriniGundelli/talent-intel/blob/main/examples/sample-report.md)

**Сравните два запроса.** В первом укажите привычное название должности. Во втором добавьте смежную должность или попробуйте найти человека по компании и задаче. Откройте один профиль, который появился только во второй выдаче. Какая строка объясняет, почему вы бы ему написали? Что ещё нужно уточнить? [Примеры построения запросов в Sourcing Sabra](https://github.com/gehtalexey/sourcing-sabra/blob/main/skills/talent-sourcer/SKILL.md)

Для справки по синтаксису поиска: [Boolean в LinkedIn](https://www.linkedin.com/help/recruiter/answer/a524335) · [поиск по сайту в Google](https://developers.google.com/search/docs/monitor-debug/search-operators/all-search-site).
